# 3. API Design

## 3.1 Overview

CampusConnect uses Firebase services as its backend. This document 
defines all service methods, providers, and data operations needed 
for implementation. Instead of traditional REST APIs, we use 
Firebase SDK methods directly from Flutter.

## 3.2 Service Architecture

Services (lib/services/):
1. auth_service.dart         - Authentication
2. firestore_service.dart    - Database operations
3. storage_service.dart      - File uploads
4. notification_service.dart - Push notifications

Providers (lib/providers/):
1. auth_provider.dart        - Auth state
2. event_provider.dart       - Event state
3. announcement_provider.dart- Announcement state

## 3.3 Auth Service (auth_service.dart)

Class: AuthService

Methods:

### signUp()
Future<String?> signUp({
  required String name,
  required String email,
  required String password,
  required String role,
  String? studentId,
  String? department,
})

Purpose: Create new user account
Returns: null on success, error message on failure

Implementation:
1. Create Firebase Auth account
2. Create user document in Firestore
3. Return null

### login()
Future<String?> login({
  required String email,
  required String password,
})

Purpose: Authenticate user
Returns: null on success, error message on failure

### logout()
Future<void> logout()

Purpose: Sign out current user

### getCurrentUser()
User? getCurrentUser()

Purpose: Get current Firebase user
Returns: User or null

### getUserData()
Future<Map<String, dynamic>?> getUserData()

Purpose: Get user document from Firestore
Returns: User data map or null

### getUserRole()
Future<String?> getUserRole()

Purpose: Get role of current user
Returns: "student", "organizer", "admin" or null

## 3.11 Error Handling

All service methods return either:
- null on success
- String (error message) on failure

Error messages:
- "Email already in use"
- "Invalid email or password"
- "Event is full"
- "Already registered"
- "Registration closed"
- "Network error"
- "Invalid QR code"
