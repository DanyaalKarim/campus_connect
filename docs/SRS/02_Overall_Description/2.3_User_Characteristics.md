# 2.3 User Characteristics

## 2.3.1 Overview

CampusConnect serves three primary user roles: Students, Organizers, and Administrators. Each role has distinct characteristics, needs, and technical proficiency levels.

## 2.3.2 User Role 1: Student

### General Characteristics

| Aspect | Details |
|--------|---------|
| Age Range | 18-25 years |
| Education | Undergraduate / Graduate students |
| Technical Skill | Medium to High (familiar with mobile apps) |
| Device | Android smartphone |
| Internet | Campus WiFi and mobile data |
| Usage Frequency | Daily to weekly |
| Primary Goal | Discover events, register, get certificates |

### Needs and Expectations

- Fast and simple event discovery
- Quick registration process
- Digital tickets (no paper)
- Push notifications for important updates
- Easy access to certificates
- Event history and records

### Technical Proficiency

- Comfortable with mobile apps
- Understands QR codes
- Can navigate multi-screen apps
- Familiar with push notifications

### User Scenarios

Scenario 1: Student opens app, sees upcoming events on home screen, taps an event, registers, gets QR ticket.

Scenario 2: Student receives push notification about venue change, opens app to verify.

Scenario 3: Student attends event, shows QR code, receives certificate after event.

## 2.3.3 User Role 2: Organizer

### General Characteristics

| Aspect | Details |
|--------|---------|
| Age Range | 20-30 years |
| Role | Society members, department representatives |
| Technical Skill | Medium (comfortable with web apps) |
| Device | Laptop / Desktop computer |
| Internet | Campus network / home internet |
| Usage Frequency | Weekly to monthly |
| Primary Goal | Create and manage events, track attendance |

### Needs and Expectations

- Simple event creation form
- Easy registration management
- Fast QR scanning for attendance
- Automatic statistics and reports
- Ability to send announcements
- Feedback from students

### Technical Proficiency

- Comfortable with web dashboards
- Can upload images
- Understands data tables and forms
- Can use a camera for QR scanning

### User Scenarios

Scenario 1: Organizer creates event, uploads poster, submits for approval.

Scenario 2: Organizer scans student QR codes at event entrance.

Scenario 3: Organizer views attendance statistics after event.

## 2.3.4 User Role 3: Administrator

### General Characteristics

| Aspect | Details |
|--------|---------|
| Age Range | 25-55 years |
| Role | University staff, faculty |
| Technical Skill | Medium to High |
| Device | Laptop / Desktop computer |
| Internet | Campus network |
| Usage Frequency | Daily |
| Primary Goal | Approve events, manage users, oversee platform |

### Needs and Expectations

- Quick event approval workflow
- User management tools
- University-wide announcement capability
- Reports and analytics
- Content moderation
- Platform-wide control

### Technical Proficiency

- Comfortable with admin dashboards
- Can manage user roles
- Understands data and reports
- Can handle bulk actions

### User Scenarios

Scenario 1: Admin reviews pending events and approves them.

Scenario 2: Admin sends university-wide announcement about campus closure.

Scenario 3: Admin disables a user account for policy violation.

## 2.3.5 User Distribution Estimate

| Role | Estimated Users |
|------|-----------------|
| Students | 500-1000 |
| Organizers | 20-50 |
| Admins | 3-5 |

## 2.3.6 User Characteristics Matrix

| Attribute | Student | Organizer | Admin |
|-----------|---------|-----------|-------|
| Interface | Mobile | Web | Web |
| Frequency | Daily | Weekly | Daily |
| Technical Skill | High | Medium | Medium-High |
| Primary Action | Register | Create | Approve |
| Peak Usage | Event time | Event creation | Weekly |
| Device | Android | Desktop | Desktop |

## 2.3.7 User Constraints

### Student Constraints
- Limited storage on phone
- Variable internet speed
- Distracted usage (short sessions)

### Organizer Constraints
- Limited time between events
- Need for quick event creation
- Multiple events at once

### Admin Constraints
- Approval turnaround time
- Policy compliance
- Data privacy concerns
