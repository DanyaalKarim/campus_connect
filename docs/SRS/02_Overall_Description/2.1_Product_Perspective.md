# 2.1 Product Perspective

## 2.1.1 System Context

CampusConnect is a new, self-contained system developed for university students, organizers, and administrators. It does not replace any existing system but provides a unified platform that consolidates multiple communication and event management processes currently spread across WhatsApp groups, Google Forms, paper-based attendance, and manual certificate generation.

## 2.1.2 System Architecture

The CampusConnect system follows a three-tier architecture:

### Presentation Layer (Client Side)
- Student Mobile App: Flutter (Android)
- Organizer Web Dashboard: Flutter Web
- Admin Web Dashboard: Flutter Web

### Business Logic Layer (Backend)
- Firebase Authentication: User authentication
- Cloud Firestore: Database and real-time sync
- Firebase Cloud Messaging: Push notifications

### Data Layer (Storage)
- Cloud Firestore: Structured data
- Firebase Storage: Images, posters, certificates

## 2.1.3 Product Components

### Component 1: Student Mobile Application
- Platform: Android 8.0+ (API 26+)
- Technology: Flutter 3.47+, Dart 3.13+
- Purpose: Student-facing event discovery and management
- Users: University students

### Component 2: Organizer Web Dashboard
- Platform: Web (Chrome, Edge, Firefox)
- Technology: Flutter Web
- Purpose: Event creation and management
- Users: Society members, department organizers

### Component 3: Admin Web Dashboard
- Platform: Web (Chrome, Edge, Firefox)
- Technology: Flutter Web
- Purpose: Platform administration and approval
- Users: University administrators

### Component 4: Firebase Backend
- Authentication: User signup/login
- Cloud Firestore: Real-time database
- Firebase Storage: File storage
- Cloud Messaging: Push notifications

## 2.1.4 External Interfaces

### User Interfaces
- Mobile App: Flutter Material Design 3
- Web Dashboards: Flutter Web Material Design 3

### Hardware Interfaces
- Camera: For QR code scanning (organizer dashboard)
- Internet: Required for most features

### Software Interfaces
- Firebase SDK: For backend services
- QR Libraries: qr_flutter (generation), mobile_scanner (scanning)
- PDF Libraries: For certificate generation

### Communication Interfaces
- HTTPS: All Firebase communication
- WebSocket: Real-time Firestore updates
- FCM: Push notifications

## 2.1.5 User Roles and Permissions

| Role | Interface | Permissions |
|------|-----------|-------------|
| Student | Android App | View events, register, view tickets |
| Organizer | Web Dashboard | Create events, scan QR, view stats |
| Admin | Web Dashboard | Approve events, manage users, reports |

## 2.1.6 Assumptions about the Environment

- Students have Android smartphones with internet access
- University provides WiFi on campus
- Organizers have access to computers with browsers
- Firebase services are available and reliable
- Users are familiar with basic mobile/web apps

## 2.1.7 Product Constraints

- Must use Flutter for cross-platform consistency
- Must use Firebase for backend
- Must support Android 8.0+ (API 26+)
- Must work on screens from 5" to 7"
- Must be available in English
