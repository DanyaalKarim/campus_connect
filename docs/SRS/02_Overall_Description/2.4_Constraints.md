# 2.5 Assumptions and Dependencies

## 2.5.1 Overview

This section lists the assumptions made during requirements analysis and the dependencies on external factors that affect the project.

## 2.5.2 Assumptions

### A. User Assumptions

| ID | Assumption | Impact if False |
|----|------------|-----------------|
| A-01 | All students have Android smartphones | Cannot use app |
| A-02 | Students have internet access on campus | Cannot use real-time features |
| A-03 | Students are familiar with mobile apps | Training needed |
| A-04 | Students can scan and understand QR codes | Alternative needed |
| A-05 | Organizers have access to computers | Web dashboard unusable |
| A-06 | Organizers can use web browsers | Training needed |

### B. Technical Assumptions

| ID | Assumption | Impact if False |
|----|------------|-----------------|
| A-07 | Firebase free tier is sufficient | Need paid plan |
| A-08 | Firebase services are reliable | Alternative backend needed |
| A-09 | Flutter supports required features | Alternative framework needed |
| A-10 | Android 8.0+ devices are common | Reduce minSdk |
| A-11 | Devices have working cameras | Cannot scan QR |
| A-12 | Push notifications work on devices | Alternative notification |

### C. Business Assumptions

| ID | Assumption | Impact if False |
|----|------------|-----------------|
| A-13 | University approves the project | Cannot deploy |
| A-14 | University provides WiFi | Users need mobile data |
| A-15 | Events are free | Payment system needed |
| A-16 | No major policy changes | Redesign needed |
| A-17 | All societies cooperate | Partial adoption |

### D. Project Assumptions

| ID | Assumption | Impact if False |
|----|------------|-----------------|
| A-18 | Team stays together | Delays |
| A-19 | Supervisor available | Delays |
| A-20 | No major scope changes | Timeline at risk |
| A-21 | Team has required skills | Learning curve |
| A-22 | Development tools work | Setup issues |

### E. Environmental Assumptions

| ID | Assumption | Impact if False |
|----|------------|-----------------|
| A-23 | Stable internet during development | Build failures |
| A-24 | No power outages | Lost work |
| A-25 | Laptops work properly | Delays |
| A-26 | Firebase not blocked by firewall | Cannot connect |

## 2.5.3 Dependencies

### A. Internal Dependencies

| ID | Dependency | Depends On |
|----|------------|------------|
| D-01 | Event registration | Authentication, Event creation |
| D-02 | QR ticket | Registration, QR generation |
| D-03 | Attendance scanning | QR ticket, Scanner |
| D-04 | Certificates | Attendance, PDF generation |
| D-05 | Feedback | Attendance, Event completion |
| D-06 | Statistics | Registrations, Attendance |

### B. External Dependencies

| D-07 | Firebase services | Google | Low |
| D-08 | Flutter SDK | Google | Low |
| D-09 | Android SDK | Google | Low |
| D-10 | University approval | University | Medium |
| D-11 | Google Play Store | Google | Low |
| D-12 | Firebase Hosting | Google | Low |

### C. Development Dependencies

| ID | Dependency | Purpose |
|----|------------|---------|
| D-14 | Android Studio | Development IDE |

| D-16 | Firebase Console | Backend management |
| D-17 | Figma | UI design |
| D-18 | Emulator/Device | Testing |

## 2.5.4 Assumption Validation

Each assumption will be:
1. Validated during early sprints
2. Monitored throughout the project
3. Revisited if conditions change
4. Documented if invalidated

## 2.5.5 Risk from Assumptions

| Assumption | Risk Level | Mitigation |
|------------|-----------|------------|
| A-01 (Android phones) | Low | Confirm with survey |
| A-07 (Free tier) | Medium | Monitor usage |
| A-13 (Approval) | Medium | Early communication |
| A-18 (Team stability) | Medium | Document everything |
| A-23 (Stable internet) | Medium | Offline work |
