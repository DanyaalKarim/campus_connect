# 3.2 Non-Functional Requirements

## 3.2.1 Overview

This section specifies the non-functional requirements (NFRs) for the 
CampusConnect platform. NFRs define quality attributes, performance 
criteria, and constraints that the system must satisfy. Each requirement 
has an ID, category, description, measurement criteria, and priority.

## 3.2.2 NFR Categories

- NFR-P: Performance
- NFR-SC: Scalability
- NFR-SE: Security
- NFR-RE: Reliability
- NFR-US: Usability
- NFR-MA: Maintainability
- NFR-PO: Portability
- NFR-CO: Compatibility
- NFR-AC: Accessibility
- NFR-LO: Localization
- NFR-LE: Legal & Compliance

---

## 3.2.3 Performance Requirements (NFR-P)

### NFR-P-01: App Launch Time

Description:
The app shall launch within 3 seconds on a standard Android device.

Measurement:
- Time from tap on icon to home screen visible
- Tested on: Pixel 5, Android 12, 4G network
- Average of 10 runs

Acceptance Criteria:
- 90% of launches < 3 seconds
- 100% of launches < 5 seconds

Priority: High

---

### NFR-P-02: Screen Load Time

Description:
All screens shall load within 1.5 seconds.

Measurement:
- Time from navigation action to screen rendered
- Tested on all screens

Acceptance Criteria:
- 95% of screens load < 1.5 seconds

Priority: High

---

### NFR-P-03: Firestore Query Response

Description:
All Firestore queries shall return within 1 second.

Measurement:
- Time from query sent to data received
- Tested with 1000+ records

Acceptance Criteria:
- 90% of queries < 1 second
- 100% of queries < 2 seconds

Priority: High

---

### NFR-P-04: Smooth Scrolling

Description:
List scrolling shall maintain 60 FPS.

Measurement:
- Frame rate during scrolling
- Tested on event lists with 100+ items

Acceptance Criteria:
- Average FPS >= 55
- No frame drops > 100ms

Priority: Medium

---

### NFR-P-05: Image Loading

Description:
Images shall load within 2 seconds.

Measurement:
- Time from image request to display
- Tested with 500KB images on 4G

Acceptance Criteria:
- 90% of images < 2 seconds

Priority: Medium

---

### NFR-P-06: QR Scanning Speed

Description:
QR code scanning shall complete within 2 seconds.

Measurement:
- Time from camera focused to QR decoded
- Tested with valid tickets

Acceptance Criteria:
- 95% of scans < 2 seconds

Priority: High

---

### NFR-P-07: App Size

Description:
The Android APK shall be under 30 MB.

Measurement:
- APK file size (release build)

Acceptance Criteria:
- APK size < 30 MB

Priority: Medium

---

### NFR-P-08: Memory Usage

Description:
The app shall not exceed 200 MB RAM during normal usage.

Measurement:
- RAM usage during typical session
- Tested on Android Studio Profiler

Acceptance Criteria:
- Peak usage < 200 MB

Priority: Medium

## 3.2.5 Security Requirements (NFR-SE)

### NFR-SE-01: Authentication Security

Description:
All authentication shall use Firebase Auth with secure tokens.

Measurement:
- Token-based auth
- HTTPS only

Acceptance Criteria:
- No plain-text passwords
- All traffic HTTPS

Priority: Critical

---

### NFR-SE-02: Role-Based Access Control

Description:
The system shall enforce role-based permissions via Firestore Rules.

Measurement:
- Rules tested for each role
- Unauthorized access blocked

Acceptance Criteria:
- Students cannot create events
- Organizers cannot approve events
- Admins have full access

Priority: Critical

---

### NFR-SE-03: Data Encryption

Description:
All data in transit shall be encrypted (HTTPS/TLS).

Measurement:
- All Firebase communication encrypted

Acceptance Criteria:
- No unencrypted communication

Priority: Critical

---

### NFR-SE-04: Password Policy

Description:
Passwords shall meet minimum security requirements.

Measurement:
- Min 6 characters
- Firebase enforced

Acceptance Criteria:
- Weak passwords rejected

Priority: High

---

### NFR-SE-05: Session Management

Description:
Sessions shall expire appropriately.

Measurement:
- Firebase session tokens
- Auto-logout after inactivity

Acceptance Criteria:
- Sessions expire after 30 days
- Logout clears session

Priority: High

---

### NFR-SE-06: Input Validation

Description:
All user inputs shall be validated to prevent injection.

Measurement:
- Input sanitization
- Firestore rules validation

Acceptance Criteria:
- No malicious inputs accepted

Priority: Critical

---

### NFR-SE-07: Data Privacy

Description:
User data shall not be shared with third parties.

Measurement:
- Firebase privacy policy
- No third-party analytics

Acceptance Criteria:
- Data stays within Firebase

Priority: High

---

### NFR-SE-08: File Upload Security

Description:
Uploaded files shall be validated for type and size.

Measurement:
- File type whitelist
- Size limits

Acceptance Criteria:
- Only images allowed
- Max 5 MB per file

Priority: High
