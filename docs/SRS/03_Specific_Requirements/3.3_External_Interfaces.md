# 3.3 External Interface Requirements

## 3.3.1 Overview

This section describes the external interfaces of the CampusConnect 
system, including user interfaces, hardware interfaces, software 
interfaces, and communication interfaces.

## 3.3.2 User Interfaces (UI)

### UI-01: Student Mobile App

Platform: Android 8.0+

Design System: Material Design 3

Screens:
- Splash Screen
- Login Screen
- Signup Screen
- Home Screen (Events, Announcements, Featured)
- Events List Screen
- Event Details Screen
- Registration Screen
- My Events Screen
- QR Ticket Screen
- Announcements Screen
- Profile Screen
- Certificates Screen
- Feedback Screen

Characteristics:
- Mobile-first design
- Bottom navigation (5 tabs)
- Card-based event display
- QR code display
- Push notification support

### UI-02: Organizer Web Dashboard

Platform: Web (Chrome, Edge, Firefox)

Design System: Material Design 3

Screens:
- Login Screen
- Dashboard (Statistics)
- Create Event Screen
- Manage Events Screen
- QR Scanner Screen
- Announcements Screen
- Feedback Screen
- Reports Screen

Characteristics:
- Desktop-optimized
- Sidebar navigation
- Data tables
- Forms for event creation
- Charts for statistics

### UI-03: Admin Web Dashboard

Platform: Web (Chrome, Edge, Firefox)

Design System: Material Design 3

Screens:
- Login Screen
- Dashboard (Statistics)
- Event Approval Screen
- Manage Societies Screen
- Manage Users Screen
- Announcements Screen
- Reports Screen
- Settings Screen

Characteristics:
- Desktop-optimized
- Admin-focused layout
- Bulk actions
- Approval workflows
- Platform-wide statistics

## 3.3.3 Hardware Interfaces

### HI-01: Camera

Purpose: QR code scanning for attendance

Platform: Organizer Web Dashboard

Requirement:
- Must have working camera
- Permission required
- Min resolution: 720p
- Auto-focus recommended

### HI-02: Device Storage

Purpose: Cache data offline

Platform: Android App

Requirement:
- Min 50 MB free space
- For cached images and data

### HI-03: Network Interface

Purpose: Internet connectivity

Platform: All

Requirement:
- WiFi or mobile data
- Min speed: 1 Mbps
- HTTPS supported

## 3.3.4 Software Interfaces

### SI-01: Firebase Authentication

Purpose: User authentication

Version: Latest stable

Interface:
- SDK: firebase_auth
- Methods: signInWithEmailAndPassword, createUserWithEmailAndPassword
- Returns: UserCredential, User

### SI-02: Cloud Firestore

Purpose: Database operations

Version: Latest stable

Interface:
- SDK: cloud_firestore
- Methods: collection(), doc(), get(), set(), update()
- Returns: DocumentSnapshot, QuerySnapshot

### SI-03: Firebase Storage

Purpose: File storage

Version: Latest stable

Interface:
- SDK: firebase_storage
- Methods: ref(), putFile(), getDownloadURL()
- Returns: TaskSnapshot, String (URL)

### SI-04: Firebase Cloud Messaging

Purpose: Push notifications

Version: Latest stable

Interface:
- SDK: firebase_messaging
- Methods: getToken(), onMessage, onBackgroundMessage
- Returns: String (token), RemoteMessage

### SI-05: QR Code Libraries

Purpose: QR generation and scanning

Packages:
- qr_flutter: For generating QR codes
- mobile_scanner: For scanning QR codes

### SI-06: PDF Generation

Purpose: Certificate generation

Packages:
- pdf: For creating PDFs
- printing: For printing/sharing

### SI-07: State Management

Purpose: App state management

Packages:
- provider: For simple state management
- Or riverpod: For advanced state

### SI-08: Navigation

Purpose: Screen navigation

Packages:
- go_router: For declarative routing

## 3.3.5 Communication Interfaces

### CI-01: HTTPS

Purpose: All Firebase communication

Protocol: TLS 1.2+

Port: 443

Data Format: JSON

### CI-02: WebSocket

Purpose: Real-time Firestore updates

Protocol: WSS

Port: 443

Data Format: Binary/JSON

### CI-03: Push Notification Protocol

Purpose: FCM notifications

Protocol: HTTP/2

Port: 443

Data Format: JSON

### CI-04: Email (Password Reset)

Purpose: Password reset emails

Protocol: SMTP (via Firebase)

Port: 587/465

Trigger: Firebase Auth

## 3.3.6 API Endpoints

### Firebase Auth Endpoints

- Sign up: Handled by SDK
- Login: Handled by SDK
- Password reset: Handled by SDK
- Token refresh: Automatic

### Firestore Collections

- /users/{userId}
- /events/{eventId}
- /registrations/{regId}
- /announcements/{annId}
- /attendance/{attId}
- /feedback/{fbId}
- /societies/{societyId}
- /certificates/{certId}

### Storage Paths

- /event_posters/{eventId}.jpg
- /profile_images/{userId}.jpg
- /event_photos/{eventId}/{photoId}.jpg
- /certificates/{certId}.pdf

## 3.3.7 Interface Constraints

- All interfaces must use HTTPS
- All Firebase services must be latest stable
- All packages must be compatible
- All interfaces must handle errors gracefully
- All communication must be within Firebase ToS limits

## 3.3.8 Interface Diagrams

User -> Mobile App -> Firebase Auth -> Firestore -> Storage
User -> Web Dashboard -> Firebase Auth -> Firestore -> Storage
Admin -> Admin Dashboard -> Firebase Auth -> Firestore
System -> FCM -> User Device (Push Notification)
